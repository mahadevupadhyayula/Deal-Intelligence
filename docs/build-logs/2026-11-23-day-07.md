## 1. What was built
- `agents/guardrails/`: `sanitize` (invisible-character removal, model-text cleaning), `untrusted` (nonce-delimited wrapping), `injection` (pattern scan, canary guard), `redact` (secrets, PII, log filter), `limits` (Redis rate limiter, active-job cap, daily quota), `usage` (metering decorators, `UsageRepo`), `tracing` (LangSmith anonymiser)
- Migration `0006_tenant_usage.sql` (forced RLS); `JOB_KINDS`/`PROVIDER_KINDS` split; new settings and `.env.example` entries
- API admission in `POST /v1/jobs` (rate limit, per-tenant advisory lock, cap, quota, `429` + `Retry-After`); worker quota re-check, metering, post-outcome usage flush, redacted errors, log and trace redaction at startup
- Lead Research: sanitise-once source ingestion, injection and hidden-character flags (`flags_detail` on the evaluation), nonce prompt wrapping with canary, model-text hygiene, and an evidence-overlap rule (an injected instruction can never be evidence)

## 2. What it achieves
Scraped web text can no longer forge its own delimiters, hide instructions in invisible characters, supply its own instructions as evidence, or smuggle markup into stored fields. One tenant cannot flood the queue or exhaust the shared provider budget, spend is metered even on failed and timed-out runs, and secrets and contact PII are kept out of stored errors, logs and traces.

## 3. Fit in the framework
Upstream: Spec 003 (queue, API, worker), Spec 005 (the agent being hardened), Spec 002 (RLS pattern).
