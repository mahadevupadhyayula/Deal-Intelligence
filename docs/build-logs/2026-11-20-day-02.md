## 2. What it achieves
Three independent isolation layers: (1) repos require a `TenantSession` and reject foreign-tenant models, (2) every statement has an explicit `WHERE tenant_id`, (3) Postgres RLS fails closed. Composite FKs stop cross-tenant references at the schema level.

## 3. Fit in the framework
Upstream: Spec 001 schemas/config/db. Downstream: Spec 003 (API/workers) opens a `TenantSession` per request/job; Spec 005 adds wiki vector tables with the same RLS pattern; Spec 007 `PostgresSaver` threads use `tenant_id` prefixes.

## Notes / decisions
- Plain SQL runner (not Alembic) and `jsonb` + promoted filter columns, as recommended in the spec.
- Superusers bypass RLS, so the app and tests connect as `app_user`; the admin URL is for migrations only.
- A DB error caught *inside* a `TenantSession` aborts the transaction; callers must wrap expected failures in `conn.transaction()` (a savepoint). Tests demonstrate this.
- `.env` placeholder password `CHANGE_ME_dev_only` is dev-only; real environments inject secrets (Spec 015).
- `DealRepo.list` is N+1 on conflicts; fine at current scale.
